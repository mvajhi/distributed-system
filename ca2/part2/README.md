# سیستم توزیع‌شده با معماری چند ماشین مجازی (بر پایه gRPC)

این بخش یک معماری غیرمتمرکز را نمایش می‌دهد که وظایف سیستم را به سه سرویس کاملاً مستقل و مجزا تقسیم کرده است. این سرویس‌ها در بستر یک شبکه کانتینری اختصاصی و با استفاده از پروتکل با کارایی بالای gRPC با یکدیگر ارتباط برقرار می‌کنند.

---

## ۱. نمای کلی معماری سیستم (System Architecture Overview)

این سیستم محیط چند ماشین مجازی مستقل را با استفاده از گره‌های شبکه‌ای کانتینری (کانتینرهای مجزا در داکر) شبیه‌سازی می‌کند:

* **ماشین اول: وب‌سرور (`web-server` / VM1)** 


* به عنوان نقطه ورود اصلی برای کاربران عمل می‌کند (مرورگر وب / پروتکل HTTP).


* هیچ پایگاه داده یا مخزن ذخیره‌سازی فایلی به صورت محلی ندارد.


* به عنوان یک کلاینت gRPC عمل کرده و با سرویس‌های احراز هویت و فایل از طریق نام شبکه آن‌ها ارتباط برقرار می‌کند.


* **ماشین دوم: سرور احراز هویت (`auth-server` / VM2)** 


* مدیریت داده‌های کاربران را به صورت کاملاً ایزوله از شبکه عمومی بر عهده دارد.


* داده‌ها را منحصراً از یک فایل داخلی پایگاه داده (`users.json`) بارگذاری می‌کند.


* صحت رمزهای عبور را به صورت ایمن و با استفاده از هَش‌های کریپتوگرافیک (Bcrypt) بررسی می‌نماید.




* **ماشین سوم: سرور فایل (`file-server` / VM3)** 


* به عنوان یک مخزن ایزوله برای فایل‌ها و دارایی‌های باینری عمل می‌کند.


* دسترسی امن به فایل‌ها را از طریق فراخوانی متد gRPC فراهم می‌آورد.


* نوع پسوند فایل (MIME type) را ارزیابی کرده و بایت‌های خام را ارسال می‌کند.

## ۲. پیکربندی و توپولوژی شبکه (Network Configuration & Topology)

برای جلوگیری از دور زدن شبکه و عدم استفاده از لوپ‌بک محلی (`localhost`)، یک شبکه اختصاصی از نوع bridge در Docker Compose تعریف شده است. پورت‌های مربوط به سرویس‌های بک‌اند (`auth-server` و `file-server`) برای امنیت بیشتر به بیرون اکسپوز (forward) نشده‌اند تا کلاینت‌های خارجی نتوانند مستقیماً با لایه دیتابیس و فایل ارتباط برقرار کنند.

| نام سرویس | پورت داخلی gRPC/HTTP | پورت اکسپوز شده روی سیستم میزبان | نقش در شبکه |
| --- | --- | --- | --- |
| `web-server` | `8080` (HTTP) | `8080:8080` | رابط عمومی سیستم و ارکستراتور کلاینت |
| `auth-server` | `50051` (gRPC) | *ندارد (محافظت شده)* | احراز هویت داخلی کاربران |
| `file-server` | `50052` (gRPC) | *ندارد (محافظت شده)* | مخزن امن و داخلی فایل‌ها |

## ۳. ابزارها و فناوری‌های مورد استفاده (Tech Stack)

* **زبان برنامه‌نویسی:** Go (v1.25+) 


* **پروتکل ارتباطی:** gRPC بر بستر HTTP/2 


* **زبان تعریف رابط:** Protocol Buffers (proto3) 


* **محیط اجرا و ارکستراسیون:** Docker & Docker Compose 


* **لایه‌ی امنیت:** مکانیزم هشینگ Bcrypt

## ۵. مشخصات زبان تعریف رابط - IDL (Interface Definition Language)

### سرویس احراز هویت (`auth.proto`)

```protobuf
syntax = "proto3";

package auth;

option go_package = "auth/authpb";

message LoginRequest {
    string username = 1;
    string password = 2;
}

message LoginResponse {
    bool success = 1;
    string message = 2;
}

service AuthService {
    rpc Login (LoginRequest) returns (LoginResponse);
}

```

### سرویس مدیریت فایل (`file.proto`)

```protobuf
syntax = "proto3";

package file;

option go_package = "grpc/filepb";

message FileRequest {
    string filename = 1;
}

message FileResponse {
    bytes data = 1;
    string content_type = 2;
}

service FileService {
    rpc DownloadFile (FileRequest) returns (FileResponse);
}

```

## ۶. فرآیندها و نحوه جریان داده‌ها در سیستم (Implementation Specifications)

1. **ارسال فرم:** وب‌سرور مقادیر ورودی `username`، `password` و `filename` را از فرم وب دریافت می‌کند.
2. 
**دست‌تکانی احراز هویت:** وب‌سرور یک درخواست RPC تحت عنوان `Login` به آدرس `auth-server:50051` ارسال می‌کند.


3. **بررسی کریپتوگرافیک:** سرویس `auth-server` فایل `users.json` را خوانده، کاربر را پیدا می‌کند و با دستور زیر صحت پسورد را می‌سنجد:
```go
err := bcrypt.CompareHashAndPassword([]byte(u.Password), []byte(password))

```


4. **فراخوانی فایل:** در صورت موفقیت‌آمیز بودن ورود، وب‌سرور بلافاصله یک متد RPC با نام `DownloadFile` به سمت `file-server:50052` ارسال می‌کند.


5. **انکودینگ Base64 و تحویل:** داده‌های باینری خام دریافت شده از سرور فایل، در لایه وب‌سرور به یک رشته استاندارد Base64 تبدیل شده و به صورت inline درون کدهای HTML تزریق می‌شوند تا مرورگر بدون نیاز به آدرس‌دهی مستقیم سرور فایل، تصویر را نمایش دهد:
```html
<img src="data:{{.ContentType}};base64,{{.ImageBase64}}" alt="Secure File">

```

## ۷. راهنمای راه‌اندازی و تست سناریوها (How to Deploy and Test)

### پیش‌نیازها

از نصب و پیکربندی صحیح ابزارهای Docker و افزونه Docker Compose روی سیستم خود مطمئن شوید.

### گام‌های اجرا

1. **بیلد و اجرای کانتینرها:**
دستور زیر را در دایرکتوری ریشه پروژه اجرا کنید:
```bash
docker compose up --build

```


2. **دسترسی به برنامه:**
مرورگر خود را باز کرده و به آدرس `http://localhost:8080` بروید.

### سناریوهای تست و ارزیابی

* **سناریوی الف: تست ورود ناموفق (تأیید مدیریت خطا)** 


* یک نام فایل معتبر (مانند `1.jpg`) وارد کنید اما مشخصات کاربری را اشتباه بنویسید.
* 
**نتیجه مورد انتظار:** وب‌سرور پیام خطای مناسب `Invalid username or password` را نشان می‌دهد. هیچ اتصالی در بک‌آند با سرور فایل جهت واکشی اطلاعات برقرار نخواهد شد.




* **سناریوی ب: تست ورود موفق و نمایش فایل** 


* اطلاعات کاربری صحیح (نام کاربری: `admin` و رمز عبور: `admin123`) را همراه با نام فایل درخواستی `1.jpg` وارد کنید.
* **نتیجه مورد انتظار:** احراز هویت با موفقیت انجام شده ، فایل باینری به صورت امن بین سرویس‌ها جابجا می‌شود ، و تصویر پروفایل به صورت یک رندر درونی Base64 به کاربر نمایش داده می‌شود.
