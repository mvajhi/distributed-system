# پروژه درس رایانش توزیع‌شده

**اعضای گروه:** سیدعلی تهامی، مهدی وجهی

**شماره دانشجویی:** ۸۱۰۱۰۱۳۹۷ و ۸۱۰۱۰۱۵۵۸

---

# مقدمه

در این پروژه یک سامانه توزیع‌شده مبتنی بر معماری میکروسرویس طراحی و پیاده‌سازی شده است. هدف اصلی پروژه آشنایی عملی با مفاهیم ارتباط بین سرویس‌ها، فراخوانی رویه از راه دور (RPC)، استقرار سرویس‌ها در محیط Docker و استفاده از سازوکارهای ارتباط ناهمگام مبتنی بر انتشار و اشتراک پیام بوده است.

سامانه نهایی از چندین سرویس مستقل تشکیل شده که هر یک مسئولیت مشخصی را بر عهده دارند و از طریق رابط‌های استاندارد با یکدیگر ارتباط برقرار می‌کنند. تمامی اجزای پروژه به گونه‌ای طراحی شده‌اند که امکان توسعه، نگهداری و استقرار مستقل آن‌ها وجود داشته باشد.

---

# ساختار پروژه

پروژه در سه بخش اصلی سازماندهی شده است:

## بخش اول

در بخش اول مفاهیم پایه و مقدمات مورد نیاز برای پیاده‌سازی سامانه مورد بررسی قرار گرفته است.

شرح کامل این بخش در فایل زیر ارائه شده است:

```text
part1/report.md
```

---

## بخش دوم

در بخش دوم معماری مبتنی بر gRPC پیاده‌سازی شده است.

در این بخش:

* سرویس احراز هویت توسعه داده شد.
* سرویس فایل پیاده‌سازی شد.
* وب‌سرور به عنوان درگاه ورود کاربران ایجاد شد.
* ارتباط میان سرویس‌ها از طریق gRPC برقرار گردید.
* تمامی سرویس‌ها در قالب کانتینرهای Docker اجرا شدند.
* تست‌های واحد برای بخش‌های مختلف سامانه نوشته شد.

گزارش کامل این بخش در فایل زیر قرار دارد:

```text
part2/report.md
```

---

## بخش سوم

در بخش سوم قابلیت پایش مصرف حافظه و ارتباط ناهمگام میان سرویس‌ها به سامانه افزوده شد.

در این بخش:

* Redis به عنوان Message Broker به سیستم اضافه شد.
* مکانیزم Publish/Subscribe پیاده‌سازی گردید.
* سرویس وب به عنوان Publisher توسعه داده شد.
* سرویس Subscriber برای دریافت اعلان‌ها ایجاد شد.
* پایش دوره‌ای مصرف حافظه انجام شد.
* در صورت عبور مصرف حافظه از آستانه تعیین شده، هشدار به صورت خودکار منتشر گردید.

گزارش کامل این بخش در فایل زیر ارائه شده است:

```text
part3/report.md
```

---

# معماری نهایی سیستم

در نسخه نهایی پروژه، سامانه از اجزای زیر تشکیل شده است:

* Web Server
* Authentication Service
* File Service
* Redis Message Broker
* Subscriber Service

وب‌سرور وظیفه تعامل با کاربر را بر عهده دارد. سرویس احراز هویت مسئول اعتبارسنجی کاربران است. سرویس فایل عملیات دسترسی به فایل‌ها را انجام می‌دهد. Redis مسئول تبادل پیام‌های ناهمگام بوده و Subscriber رخدادهای منتشرشده توسط سایر سرویس‌ها را دریافت و پردازش می‌کند.

این ساختار نمونه‌ای از یک معماری میکروسرویسی واقعی است که در آن ارتباطات همزمان و غیرهمزمان به صورت همزمان مورد استفاده قرار گرفته‌اند.

# نحوه اجرای پروژه

برای اجرای هر بخش کافی است وارد پوشه مربوطه شده و سرویس‌ها را توسط Docker Compose اجرا کنیم.

نمونه دستور اجرا:

```bash
docker compose up --build
```

پس از راه‌اندازی سرویس‌ها، سامانه آماده دریافت درخواست و انجام عملیات مربوطه خواهد بود.

جزئیات اجرای هر بخش در گزارش همان بخش توضیح داده شده است.

# نتیجه‌گیری

در این پروژه یک سامانه توزیع‌شده مبتنی بر میکروسرویس‌ها طراحی و پیاده‌سازی شد. در بخش دوم ارتباط همزمان میان سرویس‌ها با استفاده از gRPC پیاده‌سازی گردید و در بخش سوم با افزودن Redis و الگوی Publish/Subscribe، ارتباطات ناهمگام و پایش رخدادهای سیستمی نیز به سامانه اضافه شد.

معماری نهایی پروژه نمونه‌ای عملی از مفاهیم مطرح‌شده در درس سامانه‌های توزیع‌شده بوده و اجزای مختلف آن به صورت مستقل، قابل توسعه و قابل استقرار طراحی شده‌اند. برای مطالعه جزئیات فنی، نحوه پیاده‌سازی و مستندسازی سناریوهای آزمایش، به گزارش‌های اختصاصی هر بخش مراجعه شود.
